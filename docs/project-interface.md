# The board project interface

What you own when you build a board with pcbkit: the folder layout, `pcbkit.toml`, and
the hooks in `routing.py`.

Status: pre-release. The `pcbkit.toml` schema and the `routing.py` hooks are settled
here; the contracts of the other modules are added as the commands that read them are
implemented.

## Layout

```
my-board/
  pcbkit.toml          board names, stackup, router and stitching settings, fab profile, checks
  pyproject.toml       depends on pcbkit; `pcbkit new` writes it
  design.py            the circuit: parts and nets, written with pcbkit.design
  layout.py            W, H, outline, holes, P = {ref: (x, y, rot)}
  routing.py           hooks for routing (below)
  silk.py              labels and silkscreen choices (LABELS, CONN_LABELS, HIDE_REF, ...)
  footprints.py        optional: custom symbols and footprints; footprints/ holds .kicad_mod files
  specs.py             datasheet numbers and design limits the checks read
  circuits.py          optional: SPICE deck builders
  checks/test_*.py     your own checks (pytest), written against the pcbkit.check APIs
  mutants.py           MUTANTS: planted mistakes the checks must catch
  kicad/ out/ golden/ fab/    generated by pcbkit: never edit by hand
  archive/             yours: earlier revisions
```

- A command finds the project from the current directory: the nearest folder at or above
  it that holds a `pcbkit.toml`.
- `kicad/`, `out/`, `golden/` and `fab/` are regenerated by pcbkit. An edit made there,
  including one made in the KiCad GUI, is lost on the next build. Change the Python
  instead. Opening the files in KiCad to look at them is fine.
- `golden/` holds the route that passed DRC (`pcbkit promote` writes it, `pcbkit finalize`
  rebuilds from it).
- Coordinates in `layout.py` and in the routing hooks are millimetres from the board's
  top-left corner, with y pointing down. pcbkit adds a fixed (50, 50) mm offset to place
  the board on KiCad's page; the helpers below apply it, so your code never sees it.

### Importing your own modules

pcbkit imports your modules by file path (`pcbkit.project.import_project_module`). While
it does, it puts the project folder on `sys.path`, so `routing.py` can simply
`import layout`. Every importer shares one copy of each module. Name your modules so they
do not shadow an installed package (a `design.py` is fine, a `string.py` is not). An error
inside your own module reaches you as an ordinary traceback through your file.

## pcbkit.toml

```toml
[board]
stem = "my_board"            # KiCad file stem: kicad/my_board.kicad_pcb
title = "My Board"           # shown in the title block
rev = "A"                    # shown in the title block
fab_name = "My_Board_revA"   # prefix of the files written for the fab house

[stackup]
layers = 2
thickness_mm = 1.6
copper_mm = 0.035            # 1 oz; 2 oz is 0.070

[route]
freerouting_passes = 40
tries = 3
stall_timeout_s = 90
eco_unlock_reach_mm = 8.0

[stitch]
pitch_mm = 5.0
dense = [[10.0, 10.0, 30.0, 20.0, 2.0]]   # x0, y0, x1, y1, pitch
gap_limit_mm = 3.4

[fab]
profile = "pcbway"

[checks]
groups = ["kicad", "outputs", "fab"]
```

Only `[board]` is required, and every key in it is. Leave out any other table or key and
it takes the default below.

| Key | Type | Default | Meaning |
|---|---|---|---|
| `board.stem` | string | required | KiCad file stem. Letters, digits, `_`, `-` and `.`, no spaces, not starting with `.` or `-`. |
| `board.title` | string | required | Title block text. |
| `board.rev` | string | required | Revision, such as `"A"`. Quote it: `rev = 2` is an integer and is rejected. |
| `board.fab_name` | string | required | Base name of the files written for the fab house, such as `My_Board_revA_gerbers.zip`. Same character rules as `stem`. |
| `stackup.layers` | integer | `2` | Copper layers. Only `2` is accepted: pcbkit builds two-layer boards. |
| `stackup.thickness_mm` | number | `1.6` | Finished board thickness. |
| `stackup.copper_mm` | number | `0.035` | Outer copper thickness, written into the saved board's stackup. 1 oz is `0.035`, 2 oz is `0.070`. |
| `route.freerouting_passes` | integer | `40` | Maximum passes in one Freerouting run (its `-mp` option). |
| `route.tries` | integer | `3` | Freerouting runs `pcbkit route` makes before giving up when the result is not DRC-clean. |
| `route.stall_timeout_s` | integer | `90` | Seconds to wait for Freerouting to start routing before it is killed. It can hang while loading a board. |
| `route.eco_unlock_reach_mm` | number | `8.0` | With `pcbkit route --eco`, copper this close to a changed pad, and copper on the changed parts' nets, stays unlocked so Freerouting may rework it. |
| `stitch.pitch_mm` | number | `5.0` | Grid pitch of ground-stitching vias wherever both ground pours have solid copper. |
| `stitch.dense` | list of boxes | `[]` | Boxes, each `[x0, y0, x1, y1, pitch]` in layout millimetres with `x0 < x1` and `y0 < y1`, where the stitching grid uses `pitch` instead. Use it under a switching regulator, for example. |
| `stitch.gap_limit_mm` | number | `3.4` | Largest distance from any point with ground on both layers to the nearest ground via or plated ground pad. pcbkit adds vias until nothing is further away. Choose it a little under the limit you care about (a twentieth of a wavelength at your highest frequency, say). |
| `fab.profile` | string | `"pcbway"` | Whose limits and order forms to use. `"pcbway"` is the only profile so far. |
| `checks.groups` | list of strings | `["kicad", "outputs"]` | Built-in check groups to run: `kicad`, `outputs`, `fab`, `copper`, `circuit`, `esp32s3`. The default groups need nothing from `specs.py`; add the others as you write the numbers they read. |

How the file is read:

- A number accepts a TOML integer or float (`thickness_mm = 2` is fine) but never a
  boolean, and never `inf` or `nan`. Whole-number keys reject `2.0` and `"2"`.
- An unknown table or key is an error, with a "did you mean" when one is close. A typo
  never silently takes the default.
- Every problem in the file is reported together, naming the file, the table and the key.

## routing.py

The routing engine imports `routing.py` and calls the hooks below that it defines. Only
`prerouted` is required, and it may do nothing.

| Name | Signature | Called | What it does |
|---|---|---|---|
| `NETCLASSES` | `dict[str, tuple]` | when rules are applied | Net classes: name to `(track, clearance, via_d, via_drill, patterns)`, all in millimetres. `patterns` is a list of net names with KiCad's leading `/`, such as `"/VIN"`. |
| `design_rules` | `design_rules(ds) -> None` | after pcbkit's generic rules | Board-specific design rules. `ds` is `board.GetDesignSettings()`; set minimums on it, for example `ds.m_TrackMinWidth = api.mm(0.2)`. |
| `prerouted` | `prerouted(board, api) -> None` | before Freerouting | Hand-route what the autorouter should not decide, such as power paths. Tracks and vias made with `api.track` and `api.via` are locked, so Freerouting routes around them. |
| `keepouts` | `keepouts(board, api) -> None` | before Freerouting | Add rule areas (`api.keepout`): a keep-out under an antenna, a clear strip along the board edge, a region reserved for a heat sink. |
| `gnd_links` | `gnd_links(board, api) -> None` | after Freerouting, before the pours are filled | Give fine-pitch ground pads their own copper where the pour's minimum width would cut their thin necks. |
| `zones` | `zones(board, api) -> None` | after `gnd_links`, before the pours are filled | Add the ground and power pours (`api.zone`) and any pour keep-out. |
| `solid_pad_refs` | `set[str]` | while the pours are filled | References whose ground pads connect to the pour solid, with no thermal spokes: high-current connectors, a regulator's ground. |

The order within each stage follows the table: before Freerouting, rules (`NETCLASSES`
then `design_rules`), `prerouted`, `keepouts`; after it, the rules are applied again (a
copied board does not carry them), the router's result is imported, then `gnd_links`,
`zones` and `solid_pad_refs` run, and the pours are filled and stitched.

### The `api` argument

`api` is the `pcbkit.kicad.board` module: pcbkit's helpers for pcbnew, so a project rarely
needs to import pcbnew itself (it may). Besides unit helpers (`mm`, `pt`, `to_local`) it
provides:

```python
pad(board, ref, num) -> PAD                  # pad `num` of the footprint `ref`
ppos(board, ref, num) -> (x, y)              # that pad's centre, in layout mm
track(board, pts, width, netname, layer=F_Cu) -> None
                                             # a locked track through the points `pts`
via(board, x, y, netname, d=0.8, drill=0.4) -> None
                                             # a locked through-hole via
keepout(board, x0, y0, x1, y1, tracks=True, vias=True, pours=True,
        layers=("F.Cu", "B.Cu"), pts=None) -> None
                                             # a rule area; `pts` gives a polygon instead
zone(board, netname, layer, pts, priority=0, full=False,
     min_w=0.25, clearance=0.25) -> ZONE     # a copper pour; `layer` is a pcbnew layer id
                                             # (F_Cu or B_Cu); `full` = solid pad connection
rect(x0, y0, x1, y1) -> list[(x, y)]         # a rectangle's corners, for `zone` and `keepout`
clear_spot(board, near, net="GND", via_d=0.6, drill=0.3,
           reach=2.5, gap=0.25) -> (x, y)    # nearest spot a via and its track fit
```

Net names passed to these helpers have no leading `/`: `track(board, pts, 1.0, "VIN")`
finds the net `/VIN`. Only the `NETCLASSES` patterns carry the `/`, because they are
KiCad's own net-name patterns.

### A minimal routing.py

```python
from __future__ import annotations

NETCLASSES = {
    "Wide": (0.6, 0.25, 0.9, 0.5, ["/VIN", "/VOUT"]),
}


def prerouted(board, api):
    """Run the input connector's positive pin to the fuse with a wide track."""
    a = api.ppos(board, "CN1", 1)
    b = api.ppos(board, "F1", 1)
    api.track(board, [a, (b[0], a[1]), b], 1.0, "VIN")


solid_pad_refs = {"CN1"}
```

These helper signatures are part of the contract: if one changes, this page changes
with it.
